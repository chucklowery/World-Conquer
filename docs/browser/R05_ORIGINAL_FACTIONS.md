# R05 — Original faction art, palette, atlas and field gallery

**Scope:** a legally distributable **new-game** visual roster, distinct from
the 295 provisional VanillaTD engine-class wireframes. No Command & Conquer
icons, sprites, logos, extracted palettes, scenario data or third-party
textures were used. The 24 SVG masters and per-entry metadata are authored in
[`game/content/r05/`](../../game/content/r05/); attribution and redistribution
rights are recorded in [`ATTRIBUTION.md`](../../game/content/r05/ATTRIBUTION.md).

## Visual direction

| Faction | Unit silhouettes | Architecture | Remap indices |
| --- | --- | --- | --- |
| **Aster Expedition** | Split-foot rangers; light collecting pan; narrow, swept rover nose | Beacon spire, sun-sail power, field tent, modular factory | `6–9`, dark-to-highlight teal |
| **Forge Compact** | Visored, shielded guards; tracked hopper; broad anvil assault hull | Angular citadel, smelter towers, heat stacks, squared lodge, hammer works | `10–13`, dark-to-highlight rust/amber |

Each faction has one infantry, one harvester, one combat vehicle and five
structures (hub, refinery, power, barracks, factory). The neutral layer adds
two three-stage harvestable resource sprites, three terrain objects and three
six-stage tactical effects. Source colors are intentionally palette-limited;
each side's authored vectors contain its own team range and **zero** pixels
from the opposite team's range. Both share steel, stone, shadow, fire and
neutral landscape colors. Transparent palette index `0` is mandatory.

## Art-only identity and frame contracts

Every art ID is namespaced `r05.<faction>.<role>` or `r05.world.<role>`.
These are **art keys only**, not R00 entity identifiers. No production rule,
unit cost, placement permission, attack value or health simulation is
specified. The accepted R00 content registry should map these keys explicitly
when integration happens, preserving its own identity and semantics.

| Category | Source sizes | Frame ordering in each generated SHP | Health/action states |
| --- | --- | --- | --- |
| Infantry / vehicle | 24×24 / 32×32 | `idle` 8 × 1, `move` 8 × 3, `attack` 8 × 2, `damaged` 8 × 2, `destroyed` 1 × 3 = **67 frames** | Eight clockwise compass headings start at north; heading major, phase minor |
| Buildings | 48×48 | `idle` 2, `active` 3, `damaged` 2, `critical` 2, `destroyed` 3 = **12 frames** | Stationary, operational lighting, structural cracks and wreckage |
| Resource | 24×24 | `rich`, `harvested`, `depleted` = **3 frames** | Visual depletion, not a harvest economy implementation |
| Terrain | 32×32 | `normal`, `scorched` = **2 frames** | Changes appearance only; collision remains owned by the map simulation |
| Effects | 24×24 or 32×32 | `burst` frames `0–5` = **6 frames** | One-shot visual progression, no gameplay damage logic |

Frame offsets, phase counts, dimensions, footprint, anchor, source SHA-256 and
atlas rectangles are explicitly indexed per art ID in the compiled manifest.
The native `KeyFrameHeaderType` SHP bytes are generated with the existing
LCW literal encoder and immediately decoded and compared to each indexed
source frame. A sprite's health/damage states are **art contracts**, not a
promise that the legacy engine or future simulation invokes them yet.

## Deterministic build and distribution

```sh
node tools/content/test-r05.js
node tools/content/r05.js build build/r05-preview
CHROMIUM_PATH=/usr/bin/chromium node browser/engine/check-r05-gallery.js build/r05-preview
```

The builder requires Node.js 18+, without external npm dependencies. The
Chromium acceptance script requires Playwright (already installed by browser
CI). It starts its own static server, loads the manifest/atlas over HTTP,
  exercises five scene states, eight directional views and frame stepping,
  confirms visible faction pixels and rejects a
tampered atlas. It saves `gallery-proof.png` in the build directory. Open
`http://localhost:<port>/gallery.html` when serving the build directory to
browse the interactive reference gallery.

All output goes into a **new** directory. The builder never overwrites an
existing release. `manifest.json` includes input SVG SHA-256, file byte sizes,
file SHA-256 and a deterministic `contentSha256` computed from sorted paths
and hashes. No timestamps, source absolute paths or platform-dependent
rendering libraries participate. Two builds must have identical bytes.

The release directory contains `R05.PAL` (256 RGB6 entries), individual
`shapes/r05.*.SHP`, `atlases/atlas-N.png` (packed lossless RGBA with one-pixel
gutters), `gallery.html`, `gallery.js`, and `manifest.json`. All files are
source-verified and portable. The size contract is **2,500,000 bytes max**
for generated files (excluding manifest), no more than four 1024² atlas
pages. The first pack uses **552 frames, 1 atlas, 743,239 bytes**. Actual
hashes are computed by the pipeline; do not hand-edit generated byte digests.

CI runs the palette/atlas/SHP/frame tests, builds R05 into the browser engine
artifact, verifies the gallery in Chromium, and packages `/r05/gallery.html`
alongside the existing playable Courier alpha. The gallery does not import
or mutate `mission-pack.js`, `tactical-hud.js`, `native_slice_core.h`, or any
simulation registry. Existing playable behavior is separately exercised by
`browser/engine/check-runtime.js` and its regression suite.

## Handoff limitations

- All 24 entries are first production-direction visual candidates, not yet
  an approved complete game art set; additional specialized infantry, weapon
  types, damage details, theater tile joins and polished visual feedback can
  expand the roster later.
- Frame interpolation is intentionally nearest-neighbor. At tactical scale,
  compact silhouette and one-pixel colors take priority over high-resolution
  effects. The PNG atlas is RGBA and the SHP pack is palette-indexed.
- A resource *sprite* is not a map template, pathfinding occupancy, or an
  economic resource definition; a *building image* is not placeable. R04/R06/
  R07/R08/R00 must introduce and verify those gameplay semantics separately.
- Use the art IDs, not legacy engine filenames, when coordinating the R00
  registry. Add explicit mapping during integration after review.
