# R19 — Bind original faction content to actual native RTS gameplay

Implement **R19** in `https://github.com/chucklowery/World-Conquer` on a clean worktree from the newest integration branch. **This prompt is self-contained.** R05 delivered a source-verified, CC0 two-faction art pack and browser **gallery**: 24 SVG masters, 552 frames, one shared palette with two faction color ranges, SHP sprites, an RGBA atlas and deterministic manifests under `game/content/r05/` and `tools/content/r05.js`. Its `r05.aster.*`, `r05.forge.*` and `r05.world.*` identifiers are visual-only. Gallery rendering does not establish native-match usage. R00 exposes a versioned C++→browser state boundary, and R18 generalizes its house/entity/definition registries. R03/R04/R07/R08/R09 should establish real combat, maps, structures, rosters and visibility. Read `docs/browser/R05_ORIGINAL_FACTIONS.md`, `docs/browser/ARCHITECTURE.md`, `docs/rts-milestones/REVIEW-R00-R05.md`, `browser/engine/README.md`, `game/content/r05/roster.json`, `tools/content/test-r05.js` and current compiled-runtime packaging/workflows.

**Dependency gate:** **R03, R04, R05, R07, R08, R09 and R18** must all be `completed` in `docs/rts-milestones/MANIFEST.md` and integrated. Do not begin native visual integration against simulated building cards, Courier-only entities or missing production definitions; mark `blocked` with the specific missing contract. R10/R11/R14 can progress separately; R13 waits for R19's event/render binding.

**Deliverable:** an explicit, validated, versioned binding from **R18 gameplay definition IDs** and world/terrain/effect events to **R05 art keys**, palette/atlas/SHP metadata and real native C++/WASM gameplay rendering. The battlefield and minimap should depict both factions' infantry, harvesters, combat vehicles, base hubs, refineries, power plants, barracks, factories, resource depletion, terrain objects and combat effects in a native gameplay scenario, not in a test gallery or JavaScript mock. An R08-based seeded integration match is sufficient here; R11 campaign and R12 skirmish menus are not yet prerequisites. Render the right directional animation for native movement/orders and the appropriate action/damage/critical/destroyed state for combat and construction; use world/house team colors without accidentally reassigning opponent pixels. Build cards, selection portraits and production events must resolve the same definitions as the native model. Fog rules must suppress hidden actors and effects consistently in battlefield, minimap and HUD. Keep fallback rendering only for a clearly surfaced missing/corrupt art error; never allow a fallback to conceal broken production bindings during acceptance.

**Boundary and packaging requirements:** preserve native simulation authority and the R00/R18 stable **instance** IDs; never turn art IDs into entity IDs, costs, pathfinding rules or combat types. Use the source-generated R05 pack and its hash/size rules without manually editing binary output; validate atlas rectangles, SHP/palette decoding, facing/frame counts, source manifest versions and content hashes at runtime. Coordinate mapping with R03/R04/R07/R08 definitions; distinguish passability from terrain art. Package only required, licensed assets into Pages/native artifacts with a predictable loading/failure policy, bounded GPU/heap/transfer budgets, and a reproducible cross-platform build. Specify one rendering owner per sprite layer; avoid duplicating simulation in the DOM.

**Acceptance:** test every roster entry maps to exactly one known gameplay or approved world/effect role, with no dangling definitions, orphaned production cards, incorrect footprints or incompatible frame contracts. Native/JS integration tests validate animation selection, palette remaps, missing/corrupt assets, renderer bounds, fog redaction and deterministic package hashes. Run a **real Chromium WASM match**, not just `r05/gallery.html`: select and move infantry, harvest and unload, place/build/power structures, queue and spawn each unit class, engage in combat, damage/destroy a structure and reveal/re-hide enemies. Verify visually that both teams' live sprites, rotations, health stages, resource depletion and effects update from authoritative snapshots/events; include screenshots/video or deterministic pixel assertions at gameplay zoom, a mobile/narrow layout check, and the unchanged Courier extraction regression. Publish measured asset footprint and frame/memory cost, plus clear proof that the actual match loads the R05 pack. The existing R05 gallery/content tests, R00 contract tests and full browser/host CI remain green.

**Manifest protocol:** update **only R19's row** of `docs/rts-milestones/MANIFEST.md`: set `in_progress` at start, `blocked` with reason when necessary, `completed` only after native-game browser proof, tests and relevant GitHub Actions pass.
